1. About this document

This is the handover master document for the Form & Frame website and Operations app. It was written on 16 October 2026 against production commit 5354a28 (site) and is kept in the repository at docs/MASTER_DOCUMENTATION.html.

How to read the labels. Real screenshot = captured from a build of the repository files (the same files production serves), rendered in a real browser. Design prototype – not the live app = a concept page in the repository that is explicitly labelled fictional and not connected to data. Verified live = exercised on the production site. Verified by tests only = covered by automated tests with fictional data but not exercised live. Not verified / Blocked = could not be checked; the reason is stated.

Important limit: no staff sign-in was available during this review, so the signed-in Operations screens (Owner Desk, pipeline, calendar, quotes, invoices) were not captured or exercised live. Section 9 describes them from the source code and the tests, and says so on every item.

7. Configurator and pricing logic

Formula (from priceRange() in index.html)

core = (2950 + side modules + width adj + wall adj + ceiling adj + unit adj + TV adj + front adj + texture adj) × finish multiplier
sub  = core + handle + fire + lighting + glass + shelf + bridging (900 + 140/m) + AV cupboard (260)
sub  = max(1800, sub) × 0.8      (GUIDE_PRICE_FACTOR: all guide prices 20% lower)
range = [ sub×0.94 , sub×1.12 ] rounded to nearest £50

Wall adj = (wall mm − 4200)/100 × £42. Ceiling adj = (ceiling − 2700)/100 × £55 if above 2700. Unit adj = (unit height − 2100)/100 × £45 if above 2100.

8. Enquiry form

Fields: name, contact (email or phone), postcode, wall width, message, optional preferred survey window, hidden honeypot. Server rules (Edge Function submit-enquiry): required-field and format validation, honeypot rejection, IP rate limit (hashed), origin allow-list, idempotency key so a double-click or retry returns the same reference, and notification events recorded for the saved enquiry.

10. Backend architecture

Visitor browser ──POST──▶ Edge Function submit-enquiry ──▶ consultation_requests ──▶ notification_events
                                                                  │                         │
Staff PWA (/operations) ──Auth (magic link)──▶ RLS: is_staff() ───┤            retry-notifications (cron) ──▶ email (Resend)
        │                                                          │            push-new-enquiry ──────────▶ web push (VAPID)
        └─ Realtime ◀──────────────────────────────────────────────┘

Tables and relationships

profiles (staff, role) ◀── assigned_to / created_by / recorded_by / actor_id on most tables
consultation_requests (enquiry) ─┬─ request_uploads
                                 ├─ appointments ── follow_up_tasks
                                 ├─ quotes ─── accepted_quote ──▶ work_orders ──▶ invoices ──▶ invoice_payments
                                 └─ notification_events
availability_blocks · workflow_activity (audit) · push_subscriptions · business_settings · enquiry_rate_limits(+keys)

Deletes from enquiries are restricted where quotes, jobs or invoices exist (on delete restrict), so financial history cannot disappear by accident. Storage bucket project-uploads is private. Nine migrations in supabase/migrations.

Verified live: anonymous requests could read 0 rows from 10 staff tables. This cannot distinguish RLS from empty tables, so the RLS design is Verified by tests only and by reading the migrations.
