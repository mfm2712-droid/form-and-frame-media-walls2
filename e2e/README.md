# e2e/ — real-browser end-to-end tests

**Approach (and why):** `puppeteer-core` driving the Chrome already installed on the machine/CI runner, in its own `package.json` + lockfile. No browser download, no paid service, no change to the production `package.json`/Vercel build, nothing from `e2e/` is deployed (`scripts/build-public.mjs` copies named files only). Playwright was not chosen because it needs its own browser downloads and a heavier dependency tree for the same coverage here.

**What is real:** the built public site and staff app (`scripts/build-public.mjs`, fictional config), the real `operations/app.js`, the real vendored supabase-js, a real Chrome. **What is mocked (and labelled):** the Supabase network layer — `lib/mock-supabase.mjs` intercepts every request to the (fictional-key) project origin and answers from in-memory fixtures; all data is fictional. Chrome runs with DNS disabled (`--host-resolver-rules`) so nothing can leave the machine (WebSockets cannot be intercepted). The mock does **not** evaluate RLS or PostgREST filters; database rules are covered by the PGlite tests in `supabase/`.

Run: `cd e2e && npm ci && npm test` (needs Node 24 and Chrome; set `CHROME_PATH` if it is not in a standard location). Tests build `dist/public` first.

Covered: public page at 360/390/768/1280 (no overflow, one h1, anchors resolve, no unvalidated content), enquiry form validation / success / server error / rate limit / mobile nav; staff sign-in screen, magic-link request (create_user=false) and its failure, owner vs unassigned-role session, sign out; customer list de-dup + search; finance overview totals and period switch; staff role has no money UI or money requests; quotation draft (server-allocated number, never sent); status-select confirmations (decline = no write + revert; accept = PATCH); job cancel confirmation and date-order rule; notification badge, mark-all-read persistence; staff has no quote editor.
NOT covered (be honest): real Supabase/RLS/Auth/email delivery; magic-link callback and session expiry/refresh; staff app **demo mode**; quote→job creation, invoice creation, payment recording/reversal flows; appointments/calendar; push subscription (needs a service worker + permission); realtime updates; Safari/Firefox/real phones; visual regression.
